# Smart Wholesale Manager

Smart Wholesale Manager is a Streamlit application for managing wholesale business operations. It uses MySQL for company-scoped data and includes inventory, purchasing, sales, reporting, and data-based analytics.

## Features

- Company registration and login; passwords are hashed with bcrypt.
- Product and dealer creation, search, editing, and deletion.
- Purchase entry and history. Purchases increase product stock.
- Multi-product sales, sales history, saved invoices, and downloadable PDF bills. Sales are checked against available stock and reduce stock when saved.
- Dashboard summaries for sales, purchases, stock, dealers, today's activity, and inventory alerts.
- Sales, purchase, inventory, and profit reports.
- Business analytics: per-product demand and revenue estimates, sales/inventory recommendations, and stock alerts.

## Analytics Notes

Demand and revenue estimates use scikit-learn linear regression with calendar features (day, month, year, weekday, and day of year) from historical sales. At least five valid historical sales records for a product are needed. The revenue model also has a helper that evaluates its predictions with a held-out split and mean absolute error (MAE).

Business recommendations are rule-based summaries of best-selling products, highest-revenue products, and products at or below their minimum stock level; they are not generated by a machine-learning model. Predictions use limited historical/date information and should be treated as estimates, especially for dates beyond the available sales history.

`make_hash.py` is a separate optional helper: it prints a bcrypt hash from the password value in that script. Normal company registration already hashes passwords in `database/auth_db.py`, so the helper is not required to run the application. Do not put a real password in the script or commit sensitive credentials.

`.gitignore` contains comments grouping the ignore rules. It excludes `.env` because it contains local credentials, along with generated Python cache files, virtual environments, editor settings, and common operating-system files. `.env.example` is a safe template and is not excluded.

## Requirements

- Python with `pip`
- A running MySQL server and a database configured for this application
- The packages listed in `requirements.txt`

The repository does not include a database schema or migration script. The application expects tables and columns for companies, users, products, dealers, sales, purchases, demand prediction history, and sales prediction history. Create the database schema before using the application; the SQL queries in `database/` show the expected fields and relationships.

## Setup and Run

1. From the project directory, install dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

2. Create a MySQL database and set up the schema described above.

3. Copy `.env.example` to `.env` in the project root and set the connection values:

   ```dotenv
   DB_HOST=localhost
   DB_USER=root
   DB_PASSWORD=your_mysql_password
   DB_NAME=wholesale_management
   ```

   Keep `.env` private; `.gitignore` excludes it from Git.

4. Start the app:

   ```bash
   streamlit run app.py
   ```

   Streamlit normally serves it at `http://localhost:8501`.

## Manual Checks

The files in `test/` are standalone scripts, not a pytest suite. They print results and most query the configured database using the example company or product ID `1`; create suitable database records first. For example:

```bash
python test/test_connection_db.py
python test/test_demand.py
python test/test_sales_prediction.py
python test/test_recommendation.py
```

The remaining `test_*_db.py` scripts manually print database results for their respective areas. Run them from the project root so imports and `.env` loading work as expected.
